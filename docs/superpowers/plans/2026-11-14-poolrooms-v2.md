# Poolrooms v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn wave-gen v1 into a look-matched, perfectly looping YouTube ambience generator with a bouncing chrome "WAVE GEN" screensaver, extensible audio stems, and local-GPU + Modal rendering. Fix every valid PR #1 review finding first.

**Architecture:** The existing `wavegen` package keeps its shape. Pure-Python logic is pulled into small modules that are testable without Blender: frame bookkeeping, loop timing, bounce maths, audio layers and DSP, cloud planning. The Blender-side modules (`wavegen/scene/*`) consume those. All animation stays driver-based, built from loop-periodic expressions. Modal is a thin wrapper over the same `build_scene` + `render_frames` + `post.assemble` calls.

**Tech Stack:** Python 3.13, Blender 5.3 (`bpy` pip module here, desktop/official build elsewhere), numpy, ffmpeg, Modal (optional dependency), pytest.

**Spec:** `docs/superpowers/specs/2026-11-14-poolrooms-v2-design.md`

## Global Constraints

- Blender **5.3** pinned everywhere. Blender < 5.0 → fail early with a clear message.
- Every render is a loop. `render.seconds` = loop length, default **60**, at `render.fps` default **30**. Frames are `1 … N` with `N = round(seconds × fps)`, and frame `N+1` must equal frame `1`.
- Every periodic motion uses an **integer number of cycles per loop**.
- Animation is driver-based ("simple expression" drivers using `frame`, `sin`, `cos`, and so on). No Python auto-run.
- Default video audio = `room` + `crt` stems. `--audio-mix full` uses `mix`.
- Loudness: `room+crt` ≈ **−20 LUFS** integrated, `mix` ≈ **−16 LUFS**, true peak ≤ **−1 dBTP**.
- Look targets: no DOF by default; the computer's screen-space x drifts ≤ **4 %** of frame width over the loop; tile ≈ **0.13 m**.
- Render budget target: ≤ **15 s per 1080p frame** on an RTX 4070 (estimated here).
- No logos, OS artwork or brand-like details (computer, screensaver). The emblem text is exactly **"WAVE GEN"**.
- The cloud path never spends money without an estimate + confirmation or `--yes`. No secrets in the repo.
- Commits end with the session's Co-Authored-By / Claude-Session trailer lines. Push to `claude/lucid-goldberg-aw6nc3` only.
- PR replies end with the Claude Code footer (`---` / `_Generated by [Claude Code](https://claude.ai/code)_`). Never approve or merge.

## Review Focus

1. **Loop length that isn't a whole number of frames** (e.g. `seconds=59.97`): expect N rounded to an integer, and cycle counts computed from that N, so the seam stays exact. Tested in Task 5.
2. **A short loop** (e.g. `seconds=8`) with drift periods longer than the loop: expect each motion to get ≥ 1 cycle, never 0 (which would freeze it) and never a fraction. Tested in Task 5 and Task 6 (audio at 8 s).
3. **Re-using an output folder or cloud run id after changing the preset:** expect a refusal naming the mismatch, not silently mixed frames. Tested in Task 1 and Task 14.
4. **`--frames` outside `1…N`** (`0`, `N+5`) or reversed: expect a clear error before any render. Tested in Task 1.
5. **Emblem rendering on a machine with no extra fonts:** expect Blender's built-in font to be used, with the emblem still produced. Tested in Task 8.
